# Emiliano Zapata — приложение отчётности на Python

Локальное веб-приложение для трёх CSV из Mindbox. Python читает файлы, проверяет данные, рассчитывает показатели и формирует Excel и CSV. Интерфейс открывается в браузере. Сеть и дополнительные библиотеки для работы не нужны.

## Запуск

Требуется **Python 3.9 или новее**.

- **macOS:** распакуйте архив, откройте `Start.command` двойным нажатием. При запрете запуска используйте команду ниже из папки приложения.
- **Windows:** распакуйте архив и откройте `Start.bat`.
- **Любая система:** в папке приложения выполните `python3 -B app.py` (в Windows — `py -3 -B app.py`).

Приложение само выберет свободный локальный порт и откроет браузер. Если окно браузера не появилось, скопируйте адрес из окна запуска. Для остановки нажмите Ctrl+C в окне запуска. Повторный запуск создаёт новый адрес и требует повторной загрузки файлов.

## Использование

1. Для знакомства нажмите **«Попробовать на демоданных»**. Это вымышленные записи, подходящие для учебной демонстрации.
2. Для рабочего отчёта выберите три CSV: **Заказы**, **Клиенты**, **Регистрации** и нажмите **«Загрузить файлы»**.
3. Проверьте сопоставление шести полей карточки в раскрывающемся блоке.
4. Выберите обе даты и нажмите **«Построить отчёты»**.
5. Переключайтесь между продажами и регистрациями; фильтруйте отображение по бутику.
6. Нажмите **«Скачать Excel»** или **«Скачать CSV»**. Экспорт содержит все бутики; фильтр на экране меняет только отображение. Язык экспорта соответствует выбранному языку интерфейса.

В Excel пять листов: два отчёта и три листа исходных данных. Сохранены девять таблиц с фильтрами. Даты в жёлтых ячейках C4 и E4 меняются отдельно на каждом отчётном листе; формулы пересчитывают показатели в пределах загруженных дат. После смены дат фильтры таблиц требуется применить повторно. Для новых дат или новых статусов заказов необходимо загрузить обновлённые CSV в приложение.

CSV — статический снимок. Доли хранятся числами от 0 до 1, суммы и количества — числами; отсутствующие данные отмечены явно.

## Расчёты

- Продажи: шесть офлайн-бутиков, позиции со статусом `done`, только клиенты с ID. Дата — дата создания заказа в московском времени; обе границы включены.
- `OrderLinePriceOfLine` — готовая сумма позиции, повторно на количество не умножается. Возвращённые и отменённые позиции исключаются из исходного заказа.
- Покупатели и заказы уникальны в каждой группе. Итог сети исключает повторы между бутиками. Показатели сотрудников нельзя складывать для получения числа уникальных заказов и клиентов.
- Регистрация: самое раннее доступное событие клиента во всей выгрузке, затем отбор по периоду. Если история неполная, число новых клиентов может быть завышено.
- «Не купили в день регистрации»: нет выполненной позиции в любом из шести бутиков в тот же московский календарный день. Покупка до времени регистрации в тот же день тоже считается покупкой.
- Продавец берётся из позиции заказа; сотрудник регистрации — из текущей карточки клиента. История изменения сотрудника неизвестна.
- Неизвестный бутик регистрации показан отдельно и не определяется по месту покупки.
- Заполненность: имя, фамилия, отчество, дата рождения, телефон, email на момент выгрузки. Непустое значение считается заполненным; валидность не проверяется. Отсутствующая колонка или карточка — неизвестное значение, не ноль.
- Ранее зарегистрированные покупатели: московская дата покупки позже даты первой доступной регистрации. Это не доказательство повторной покупки. Продажи без даты регистрации показаны отдельно.

## Формат входных CSV

Поддерживаются UTF-8 с BOM или без него и Windows-1251, разделители `;`, `,`, табуляция, кавычки и переносы строк внутри значений. ID остаются строками, включая ведущие нули. Обязательные колонки перечислены в `engine.py`, словарь `REQUIRED`.

Заказы: `OrderIdsMindboxId`, `OrderFirstActionDateTimeUtc`, `OrderFirstActionChannelName`, `OrderCustomerIdsMindboxId`, `OrderLineQuantity`, `OrderLinePriceOfLine`, `OrderLineStatusIdsExternalId`, `OrderLineCustomFieldsConsultantPerItem`.

Клиенты: `CustomerIdsMindboxId`, `CustomerCustomFieldsConsultantWhoRegistered`, а для заполненности — шесть колонок полей карточки, определяемых автоматически или вручную.

Регистрации: `CustomerActionCustomerIdsMindboxId`, `CustomerActionDateTimeUtc`, `CustomerActionChannelName`.

Даты UTC: `YYYY-MM-DD HH:MM:SS`, также допускаются `T`, дробные секунды и конечная `Z`. Повторные ID клиентов, одинаковые строки позиций, некорректные даты, отрицательные/пустые суммы и количества вызывают понятную ошибку. Пустые файлы не принимаются.

## Устройство учебного проекта

- `app.py`: локальный HTTP-сервер, загрузка и маршруты приложения, запуск браузера.
- `engine.py`: CSV, валидация, нормализация, бизнес-правила и агрегаты. Для денежных расчётов используется `Decimal`.
- `excel.py`: генерация XLSX стандартными средствами Python (`zipfile`, XML), формулы и сохранённые результаты.
- `static/`: HTML, CSS и небольшой JavaScript для кнопок, отображения таблиц и передачи файлов. Расчётов и формирования Excel в JavaScript нет.
- `translations.json`: перевод терминов исходного отчёта; `styles.xml`: оформление Excel.
- `tests/`: проверка расчётов, CSV, XLSX, ошибок и цепочки загрузка → отчёт → экспорт.
- `demo/`: три CSV с вымышленными данными.

Здесь нет базы данных и облачного сервиса. CSV временно находятся в памяти процесса и очищаются при завершении. Приложение слушает только `127.0.0.1`; локальные запросы защищены случайным токеном. Сохраняются только файлы, которые пользователь сам скачивает. Одновременно хранится до восьми последних наборов загрузок. Лимит запроса — 128 МБ с учётом кодирования файлов.

## Проверка

Из папки приложения: `python3 -B -m unittest discover -s tests -v`.

Для запуска без автоматического открытия браузера: `python3 -B app.py --no-browser`. Можно задать порт: `--port 8765`.

Проверено на Python 3.9 в macOS. Запускатель Windows включён, но на Windows в этой среде не проверялся. Формулы XLSX проверяются отдельным табличным движком; поведение конкретной версии Microsoft Excel требует проверки в ней.
